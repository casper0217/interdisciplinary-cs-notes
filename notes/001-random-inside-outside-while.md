`random.randint()`**의 위치에서 시작한 질문: 숫자 맞히기, 확률분포, OTP**  
*출발점: 직접 작성한 숫자 맞히기 게임에서 난수 생성 위치를 바꿔보며 생긴 의문.*  
*작성 구분: 아래 두 게임은 사용자 제공 코드이며 두 번째 코드의 들여쓰기만 정리했다. 수식·해설·추가 계산 코드는 AI의 도움으로 작성한 학습 초안이다. 직접 이해하고 확인한 범위에 맞춰 수정하며 기록한다.*  
**1. 같은 게임인데 난수 생성 위치가 다르면?**  
**코드 A — 반복문 밖에서 정답 생성**  
```  
import random  
   
 print("=" * 3 + " 숫자 맞추기 게임 " + "=" * 3)  
 random_number = random.randint(1, 100)  
   
 while True:  
     user_input = input("숫자를 입력하세요: ")  
   
     if random_number == int(user_input):  
         print("Pass!")  
         break  
     elif random_number > int(user_input):  
         print("Up!")  
     else:  
         print("Down!")  
   
```  
   
   
**코드 B — 반복문 안에서 정답 생성**  
```  
import random  
   
 print("=" * 3 + " 숫자 맞추기 게임 " + "=" * 3)  
   
 while True:  
     random_number = random.randint(1, 100)  
     user_input = input("숫자를 입력하세요: ")  
   
     if random_number == int(user_input):  
         print("Pass!")  
         break  
     elif random_number > int(user_input):  
         print("Up!")  
     else:  
         print("Down!")  
   
```  
차이는 한 줄의 위치지만, **정답이 유지되는 시간**이 달라진다.  
  
|  |  |  |  
| - | - | - |  
| **구분** |  **코드 A** |  **코드 B** |  
| 난수 생성 |  게임 시작 시 한 번 |  입력을 받을 때마다 |  
| 정답 |  게임이 끝날 때까지 고정 |  매 시도 새로 추출 |  
| 이전 Up/Down |  다음 추측에도 유효 |  다음 정답의 범위를 좁혀주지 않음 |  
| 모든 숫자를 한 번씩 입력 |  반드시 한 번은 정답을 만남 |  반드시 맞힌다는 보장 없음 |  
  
   
코드 B에서 새로 추출한 숫자는 이전과 같을 수도 있다. **독립적으로 다시 뽑는 것과 반드시 다른 값으로 바꾸는 것은 다르다.** 이후 이론은 각 추출이 균등하고 독립이라는 모형을 사용한다. Python의 `random`은 실제로는 의사난수 생성기이다.\[1\]  
여기서 질문이 이어진다.  
- 코드 A에서 순서대로 입력하면 몇 번 만에 성공할까?  
- 코드 B에서 내 입력만 `50`으로 고정하면 어떻게 될까?  
- 정답이 고정됐다는 이유만으로 이산균등분포라고 할 수 있을까?  
- 이 차이를 로그인 OTP에 적용하면 어떤 보안 조건이 중요할까?  
**2. 먼저 무엇의 분포인지 정하기**  
정답을 나타내는 변수와 **성공까지의 시도 횟수**는 다른 확률변수이다.  
- X: 생성된 정답. 후보가 \$1,2,\dots,N\$이면 P(X=x)=1/N.  
- T: 처음 정답을 맞힌 시도 번호. 첫 시도에 맞으면 T=1.  
이 글에서는 \$N=100\$을 기본으로 하고, 유효한 정수를 한 번 입력하고 비교하는 것을 한 시도로 센다. 입력 오류나 범위 밖 입력은 확률모형에서 제외한다.  
**정답 \$X\$가 균등분포여도 시도 횟수 \$T\$가 항상 균등분포인 것은 아니다.** \$T\$의 분포를 정하려면 추측 전략도 정해야 한다.  
**3. 코드 A: 언제 이산균등분포가 나타날까?**  
정답을 한 번 뽑아 고정하고, 힌트는 무시한 채 `1 → 2 → 3 → … → 100` 순서로 추측한다고 하자.  
정답이 1이면 첫 번째에, 50이면 쉰 번째에, 100이면 백 번째에 성공한다. 정답은 각각 같은 확률로 선택되므로 성공 위치도 같은 확률을 갖는다.  
P(T=k)=\frac{1}{N},\qquad k=1,2,\dots,N  
이것이 \*\*이산균등분포(discrete uniform distribution)\*\*이다. 1부터 순서대로가 아니더라도, 정답과 무관하게 미리 정한 비중복 순서라면 같은 결론을 얻는다.  
**평균과 분산**  
기댓값은 각 시도 번호에 그 확률을 곱해 더한다.  
E\[T\]=\sum\_{k=1}^{N}kP(T=k) =\frac{1}{N}\frac{N(N+1)}{2} =\frac{N+1}{2}  
제곱의 평균은 다음과 같다.  
E\[T^2\]=\frac{1}{N}\sum\_{k=1}^{N}k^2 =\frac{(N+1)(2N+1)}{6}  
따라서 분산은  
\operatorname{Var}(T)=E\[T^2\]-E\[T\]^2 =\frac{N^2-1}{12}  
\$N=100\$이면 평균은 **50.5회**, 분산은 **833.25회²**, 최악의 시도 횟수는 **100회**이다. 평균과 최악값은 서로 다른 양이다.  
**k번 안에 성공할 확률**  
처음 \$k\$개 후보 중 정답이 있으면 성공하므로, 정수 \$0\le k\le N\$에서  
P(T\le k)=\frac{k}{N}  
50번까지 탐색하면 성공 확률 50%, 100번까지 탐색하면 100%이다.  
**원본에는 Up/Down이 있는데?**  
위 결론은 **힌트를 이용하지 않는 비중복 탐색**의 결과다. 원본 코드처럼 대소 힌트가 있으면 범위를 반씩 줄이는 이진 탐색(binary search)을 할 수 있다.  
  
|  |  |  |  |  
| - | - | - | - |  
| **전략** |  **정보 이용** |  **N=100의 최대 시도 횟수** |  **질의 수의 시간복잡도** |  
| 순차 탐색 |  하나씩 확인 |  100회 |  O(N) |  
| 이진 탐색 |  대소 힌트로 절반씩 제외 |  7회 |  O(\log N) |  
  
   
여기서는 한 번의 추측과 응답을 한 질의로 센다. 이진 탐색에서는 성공 위치가 1\~100에 균등하지 않다. 따라서 **“코드 A이므로 T가 이산균등분포다”라는 설명에는 추측 전략이라는 전제가 빠져 있다.**  
**4. 코드 B: 내 추측을 고정해도 기하분포일까?**  
내 입력은 매번 `50`으로 유지하고, 정답만 매 시도 독립적으로 추출한다고 하자.  
매번 정답이 50일 확률은 동일하다.  
p=P(\text{한 번의 성공})=\frac{1}{100},\qquad q=1-p=\frac{99}{100}  
첫 번째에 성공하려면 곧바로 맞히면 된다. 두 번째에 처음 성공하려면 한 번 실패한 뒤 성공해야 한다. 세 번째라면 두 번 실패한 뒤 성공해야 한다.  
P(T=1)=p,\qquad P(T=2)=qp,\qquad P(T=3)=q^2p  
일반화하면  
\boxed{P(T=k)=(1-p)^{k-1}p},\qquad k=1,2,\dots  
독립 시행에서 첫 성공까지의 시도 횟수를 나타내는 \*\*기하분포(geometric distribution)\*\*이다.\[2\] 이 글은 실패 횟수가 아니라 성공한 시행까지 포함하여 센다.  
고정 추측을 1이나 100으로 바꾸어도 확률은 같다. 과거 결과에 따라 다음 추측을 바꾸더라도, 새 정답을 미리 알 수 없고 항상 유효한 숫자를 고르면 다음 성공 확률은 여전히 \$1/N\$이다. 과거 힌트가 다음 정답에 관한 정보를 주지 않기 때문이다.  
**평균과 분산은 왜 이렇게 될까?**  
\$q=1-p\$라 하면, 기하급수의 합을 미분하여  
\sum\_{k=0}^{\infty}q^k=\frac{1}{1-q} \quad\Longrightarrow\quad \sum\_{k=1}^{\infty}kq^{k-1}=\frac{1}{(1-q)^2}  
를 얻는다. 따라서  
E\[T\]=\sum\_{k=1}^{\infty}kq^{k-1}p=\frac{1}{p}  
한 번 더 미분하면 \$\sum\_{k=2}^{\infty}k(k-1)q^{k-2}=2/(1-q)^3\$이다. 여기서  
E\[T(T-1)\]=\frac{2q}{p^2},\qquad E\[T^2\]=\frac{2-p}{p^2}  
이므로  
\operatorname{Var}(T)=\frac{1-p}{p^2}  
\$p=0.01\$을 대입하면 평균은 **100회**, 분산은 **9,900회²**이다. 순차 탐색보다 분산이 크다는 것은 성공 시점의 퍼짐도 더 크다는 뜻이다.  
**평균 100회면 100번 안에 반드시 성공할까?**  
그렇지 않다. \$k\$번 모두 실패할 확률을 먼저 구하면 \$q^k\$이므로,  
\boxed{P(T\le k)=1-(1-p)^k}  
이다.  
  
|  |  |  |  
| - | - | - |  
| **시도 횟수 k** |  **고정 정답·비중복 순차 탐색** |  **독립 갱신·고정값 추측** |  
| 1 |  1% |  1% |  
| 10 |  10% |  약 9.56% |  
| 50 |  50% |  약 39.50% |  
| 100 |  100% |  약 63.40% |  
| 299 |  100% |  약 95.05% |  
  
   
기하분포는 어떤 유한한 k\$에서도 실패 확률 (1-p)^k\$가 양수다. **평균은 100회지만, 반드시 성공을 보장하는 유한한 시도 횟수는 없다.**  
95% 이상 성공하려면  
1-(1-p)^k\ge0.95 \quad\Longrightarrow\quad k\ge\frac{\ln(0.05)}{\ln(1-p)}  
이고, \$p=0.01\$에서는 올림하여 299회가 필요하다.  
또한 기하분포에는 무기억성(memorylessness)이 있다.  
P(T>s+t\mid T>s)=\frac{q^{s+t}}{q^s}=q^t=P(T>t)  
이미 여러 번 실패했다고 해서 다음 성공이 더 가까워지는 것은 아니다. 반대로 고정 정답·비중복 탐색에서는 실패할 때마다 후보가 줄어, \$k\$번째까지 도달했을 때 그 시행의 성공 확률은 \$1/(N-k+1)\$로 증가한다.  
**5. 정답과 추측 중 무엇을 고정했는지에 따라 달라진다**  
  
|  |  |  |  
| - | - | - |  
| **정답** |  **내 추측** |  **첫 성공 횟수 T의 성질** |  
| 균등하게 한 번 생성 후 고정 |  정해진 순서로 중복 없이 |  1\~N 이산균등분포 |  
| 고정 |  매번 독립 균등 추측, 중복 허용 |  기하분포, p=1/N |  
| 고정 |  특정 값만 반복 |  처음 맞거나 영원히 실패 |  
| 매번 독립 균등 갱신 |  특정 값만 반복 |  기하분포, p=1/N |  
  
   
세 번째 경우는 중요하다. 정답이 73으로 유지되는데 50만 반복하면 성공하지 못한다. 정답을 처음 균등하게 생성한 전체 게임들에 대해 보면  
P(T=1)=\frac1N,\qquad P(T=\infty)=1-\frac1N  
이다. \$N>1\$에서는 성공까지 기다리는 횟수의 기댓값도 무한대다. **한 번의 성공 확률이 1/N이라는 사실만으로 반복 전체가 기하분포가 되는 것은 아니다.**  
**6. 기존 문법으로 누적 확률 계산해 보기**  
아래는 원본과 구분되는 **AI 작성 추가 계산 코드**이다. 시뮬레이션 결과가 아니라 위 수식에 숫자를 대입한 이론값을 출력한다. 외부 라이브러리는 필요 없다.  
```  
n = 100  
 p = 1 / n  
 attempts = [1, 10, 50, 100, 299]  
   
 for k in attempts:  
     if k <= n:  
         fixed_probability = k / n  
     else:  
         fixed_probability = 1  
   
     refreshed_probability = 1 - (1 - p) ** k  
   
     print(f"{k}회 이내 성공")  
     print(f"고정 정답·비중복 탐색: {fixed_probability * 100:.2f}%")  
     print(f"독립 갱신·고정값 추측: {refreshed_probability * 100:.2f}%")  
   
```  
`**`는 거듭제곱이다. `(1 - p) ** k`는 \$k\$번 모두 실패할 확률이다. f-string의 `:.2f`는 소수점 둘째 자리까지 표시한다.  
후속 실험에서는 원본의 입력을 자동 추측으로 바꾸고, 여러 게임의 실제 평균이 50.5와 100에 가까워지는지 확인할 수 있다. 이 글의 수치 표는 그 실험을 했다고 주장하는 표가 아니다.  
**7. 로그인 OTP에 연결하면 어떤 질문이 생길까?**  
**“유효시간이 없다”는 말부터 구분해야 한다**  
처음에는 유효시간이 없는 OTP를 코드 B에 연결할 수 있을 것처럼 보인다. 하지만 **유효시간과 갱신 시점은 별개의 조건**이다.  
  
|  |  |  
| - | - |  
| **인증 코드의 동작** |  **대응하는 모형** |  
| 한 번 발급한 코드가 만료 없이 유지 |  코드 A의 고정 정답 |  
| 인증 시도마다 새 코드로 교체 |  코드 B의 갱신 정답 |  
| 일정 시간 동안 유지한 뒤 갱신 |  기간 안에서는 A, 기간 사이에서는 갱신 |  
  
   
실제 TOTP(time-based one-time password)는 비밀키와 시간 단계로 계산된다. 매 로그인 요청마다 `random.randint()`를 호출하는 방식이 아니다. RFC 6238의 기본 시간 단계는 30초이며, 서버의 허용 시간창도 수락 범위에 영향을 준다.\[3\]  
**6자리 코드와 최대 5번의 시도**  
선행 0을 포함한 `000000`\~`999999`를 가정하면 \$N=10^6\$이다. 누출·편향이 없는 이상적인 균등 코드 모형에서 다음과 같다.  
  
|  |  |  
| - | - |  
| **조건** |  **최대 5번 안의 성공 확률** |  
| 정답 고정·서로 다른 5개 추측 |  5/10^6=0.0005\\% |  
| 정답 매번 독립 갱신·고정값 추측 |  1-(1-10^{-6})^5\approx0.000499999\\% |  
| 정답 고정·같은 값 5번 추측 |  1/10^6=0.0001\\% |  
  
   
5번처럼 적은 횟수에서는 첫 두 모형의 차이가 매우 작다. 하지만 무제한 시도라면 고정 정답·비중복 탐색은 100만 회에서 성공을 보장하고, 독립 갱신 모형은 같은 보장이 없다. **갱신한다는 사실만으로 무제한 추측 문제가 해결되는 것은 아니다.**  
최대 \$L\$번에서 중단하면 성공 확률과 실제 수행량도 구분해야 한다. 기하분포에서 수행 횟수 \$A=\min(T,L)\$의 평균은  
E\[A\]=\sum\_{j=0}^{L-1}P(T>j) =\frac{1-(1-p)^L}{p}  
이다. 제한 때문에 끝난 실패를 “마지막 시행에서 성공”으로 세어서는 안 된다.  
**주기적으로 갱신되는 경우**  
각 기간의 코드가 독립 균등이고, 기간 j 안에서 서로 다른 \$m_j\$개를 추측하며 \$0\le m_j\le N\$이라고 하자. 기간 내 성공 확률은 \$m_j/N\$이고 전체 성공 확률은  
P(\text{적어도 한 번 성공}) =1-\prod_j\left(1-\frac{m_j}{N}\right)  
이다. 같은 숫자를 한 기간에 여러 번 넣으면 그 기간의 성공 확률은 여전히 \$1/N\$이다. 다음 기간에 새 코드가 생성되어야 새 기회가 생긴다. 실제 허용 시간창이 겹치는 경우에는 기간 독립 전제가 맞는지 추가로 확인해야 한다.  
**8. 그렇다면 어떤 보완책이 필요한가?**  
이 분석이 직접 다루는 것은 암호 알고리즘을 깨는 문제가 아니라 **온라인 추측과 인증 정책의 문제**다. 안전한 암호 알고리즘으로 만든 코드도 작은 출력 공간에 무제한 추측을 허용하면 위험이 누적된다.  
  
|  |  |  |  
| - | - | - |  
| **관찰한 문제** |  **검토할 보완책** |  **확률모형과의 연결** |  
| 시도를 계속하면 성공 확률 누적 |  계정별 실패 제한, 요청 속도 제한 |  가능한 총 시도 수 L을 제한 |  
| 오래된 코드에 계속 대입 가능 |  명시적인 유효시간 |  한 코드의 노출·추측 기간 제한 |  
| 성공한 코드를 다시 제출 가능 |  성공한 OTP의 재사용 방지 |  최초 추측과 별개로 재전송 차단 |  
| 갱신·새 세션마다 제한 초기화 |  실패 집계를 세션·재발급과 연계 |  기간을 바꿔 총 제한을 우회하지 않게 함 |  
| 오류 응답이 대소 관계를 노출 |  정답의 대소 정보를 주지 않는 응답 |  이진 탐색에 필요한 힌트 차단 |  
| 예측 가능한 코드 생성 |  검증된 OTP 구현·안전한 키 관리 |  균등·예측 불가능성 가정의 기반 확보 |  
  
   
NIST 지침은 짧은 OTP 출력에 대한 시도 제한과 유효한 OTP의 한 번만 수락을 요구한다.\[4\] Python 공식 문서도 `random`을 보안 목적으로 사용하지 않도록 안내한다.\[1\] 단순히 난수 함수를 교체하는 것만으로 완전한 인증 시스템이 되는 것은 아니다.  
**9. 현재 이해와 다음 질문**  
한 줄의 위치 차이에서 시작했지만, 분포를 결정하려면 **정답의 수명·추측 전략·실패에서 얻는 정보**를 함께 정해야 한다는 점으로 이어졌다.  
- 코드 A의 성공 횟수는 비중복 순차 탐색이라는 조건에서 이산균등분포다.  
- 코드 B는 독립 균등 갱신을 가정하면 고정값을 추측해도 기하분포다.  
- 기댓값, 유한한 최악 횟수, 제한 내 성공 확률은 다른 질문이다.  
- OTP에서는 코드 생성뿐 아니라 유효시간과 실패 제한의 범위가 중요하다.

- 정답이 균등하지 않으면 어떤 추측 순서가 평균 시도 수를 줄일까?
